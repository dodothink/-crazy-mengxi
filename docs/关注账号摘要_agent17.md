# 关注账号摘要 · agent.17

## 桌面入口
工作台 → 运行与开关 → 关注账号摘要。填写多个准确用户名，选择每隔若干分钟（至少5分钟）或每天固定时间，填写时区（例如 Europe/Dublin、Asia/Shanghai），保存后点开始。默认关闭，未预设监控对象。名单按钮支持逐人启停，修改后保存。

可筛选帖子编号、板块编号，选账号新主题、账号回复/新楼，以及这些账号主题中其他人的新回复；可合并或逐人推送。第一次、名单或范围改变、存档来源/代数变化时只建立基线，不回推历史。时间未知或早于首次基线的新发现旧楼不推送。已有楼正文修改标为修改。

## Telegram
/menu → 关注账号摘要；或发送 /digest。按钮提供开始、停止、立即总结及设置状态。与电脑共用数据；仅已绑定私人账号可操作。

- /digest add 用户甲,用户乙：添加多人。
- /digest remove 用户甲：移除。
- /digest on 用户甲 或 /digest off 用户甲：逐人启停。
- /digest interval 360：每6小时。
- /digest time 09:00,21:00 Asia/Shanghai：北京时间每天两次。
- /digest scope all：全部已存档帖子；/digest scope 123,456 152：指定帖子和板块。
- /digest kinds topics,replies,threadReplies：新主题、本人回复、其主题的他人回复。按需删去类型。
- /digest group user 或 merged：按人分开或合并。
- /digest empty on 或 off：没有新内容是否通知。
- /digest now：请求立即处理，首次只建基线。
- /digest start 或 stop：开始、停止。

停止会取消尚未投递的本模块消息；已发送的无法撤回，正在进行的网络请求可能已经发出。现有回帖任务、审核队列不受影响。

## 内容、费用与限制
使用原 Kimi Key、kimi-k3.1-pro，摘要固定 low，单次输出预算4096 tokens，与原AI每日额度共用。不传旧采样参数。只上传匹配的新楼、必要前文和引用。正文超4000字符使用注明截断的节选，每次输入约18000字符内；大量内容按段推送，每轮最多100楼，剩余留到下次计划或手动运行。失败保留未读进度，已生成段落缓存复用。

只代表本机已采内容，不保证全站覆盖。推送注明不完整存档和存档更新时间；6小时没有新写入时提示检查采集。无新增默认不调用AI、不推送。agent.17.1：逐帖JSON校验失败时隔离该帖，其他校验通过的帖子仍可摘要；推送注明隔离数量。全局清单或路径错误仍停止读取。

运行要求：电脑保持运行，Agent保持运行；上游浏览器保持运行才能有新存档。手机不能替代电脑采集。投递 pending 为排队，sent 为Telegram接口确认，needs_review 为结果不明确；不盲目重复发送。
