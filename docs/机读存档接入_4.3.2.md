## 已接入

Agent 的本机存档列表、预览、草稿阅读入口、日报与摘要读取 `_data`，不再扫描 Markdown。只读取清单列出的 JSON，不读取临时文件，不向共享存档写状态。进度保存在 Agent 自己的 runtime/agent.sqlite 的 archiveReader.v1。

首次接入等待 coverage=full，逐帖检查 SHA-256、来源、编号、版本和楼层结构后建立基线；不生成新增帖子事件、不调用 Kimi、不发送通知或发表回复。后台每分钟核对一次；用户读取时超过 30 秒也会核对。旧数据、失败记录和未知完整性不会被当作成功采集。

采用全清单哈希对账：每次核对清单，只重新读取变化的 JSON，而不是依赖日志逐行投递。这样也能覆盖日志被清理的缺口。来源变化、换代、回退或日志缺口时重新建立基线。任一已发布正文校验失败时，整批不提交游标；下次重试，错误期间不给用户返回旧缓存冒充最新数据。没有 v1 清单时明确报错，不自动退回 Markdown。

覆盖全部不等于每帖完整。重建旧帖 complete=null 很常见：可以浏览已存正文，但 AI 草稿和长帖摘要要求 complete=true 且无 lastFailure。请在上游完成全帖采集后重试；日报只统计已存内容，不代表论坛全部内容。

## 使用与诊断

刷新“疯狂的梦溪”后，打开工作台的本机存档列表，可看到协议、覆盖范围、已校验帖数、不完整帖数和不可用帖数。旧列表中的文件 ID 已改成帖子编号，遇到无效选择请刷新列表。原配对、Kimi 和 Telegram 凭据保留。

配对客户端可通过原有 Origin/Bearer 认证 POST /archive-status 查看进度和最近错误；它不返回密钥或帖子正文。

Agent 启动命令不变：在项目 agent 目录运行 Node 24 的 node server.mjs，或使用现有启动脚本。Mac 可使用 agent/runtime/node server.mjs。Windows 安装 Node 24 后在 agent 目录运行 node server.mjs。前台启动时保持该终端打开；退出后重新运行即可。没有自动开机启动承诺。
