# 超时自动发表解锁说明（4.2.5-agent.17.3-auto）

基线：4.2.5-agent.17.2（提交 b2b3bc6）。本版只做一件事：解除「逐条确认」硬闸门，
恢复「通知送达后 5 分钟无人处理即尝试发表」。采集仍只读本机存档，未改动上游协议、
存档校验、草稿生成、发帖内容校验。

## 1. 原来被锁在哪（7 处）

| # | 文件 | 原行为 |
|---|---|---|
| 1 | `agent/server.mjs` `/auto-approval` | `claim` 直接抛「本版本需要逐条确认，不支持超时自动发表」 |
| 2 | `agent/server.mjs` `/approval` | 传入 `autoAfterMs` 即抛错，并强制 `const autoAfterMs=0` |
| 3 | `agent/telegram-control.mjs` `queue()` | `op==='auto' && enabled` 时抛错，手机端无法开启 |
| 4 | `agent/telegram-control.mjs` 菜单 | `autoOn` 与 `collect` 一并抛「不支持」 |
| 5 | `extension/addons/auto-reply.js` `config()` | `LocalMode.active` 时把开关强制读成 `enabled:false` |
| 6 | `extension/addons/auto-reply.js` `setEnabled()` | `LocalMode.active` 时禁止开启 |
| 7 | `extension/addons/local-mode.js` `enforce()` | 每次加载都写回 `enabled:false` 并取消在途任务 |
| 8 | `extension/addons/control-ui.js` | 工作台开关被硬置 `disabled=true`，文案固定为「超时不发表」 |

附带修正：`telegram-control.mjs` 的 `autoOn` 分支原先不在外层 `includes(verb)` 列表里，
即使去掉抛错也进不去，已补入；`thread-tracker.js` 与菜单文案中「不会超时自动发表」
的提示同步改为当前行为。

## 2. 现在怎么开启

默认仍是关闭的。开启方式任选其一：

- 工作台：打开扩展工作台，点「逐条确认后发送 · 超时不发表」按钮 → 变为
  「超时自动发表 · 已开启（5 分钟无回复即发表）」。设置持久保存，重启浏览器不丢。
- Telegram：`/menu` → 运行控制 → 开启自动发表 → 二次确认。

关闭：同一按钮，或 Telegram 的 `autoOff`。关闭会同时取消在途倒计时。

## 3. 一次自动发表要过的关（均保留）

1. 草稿必须由用户显式点「送审」触发，生成草稿本身不会发帖。
2. `/approval` 要求已绑定本人 Telegram（`telegramBinding`）。
3. 倒计时只在 Telegram 通知确认送达（outbox `state='sent'`）后才开始，`sentAt+300000`。
4. 认领窗口 `[dueAt, dueAt+60000]`，错过不补发。
5. 认领时要求 `telegramHealth.ok` 且 10 秒内刷新过。
6. 扩展端 `assertReady` 复核：草稿引用、正文、tid、fid、`pendingApprovals` 一致，
   且 `dueAt+120000` 内。
7. `assertRunnable('post')`：发帖暂停或待人工验证时不发。
8. 电脑离线/休眠超过 90 秒、浏览器重启、`postHalted` 事件，均取消且不补发。
9. 认领是一次性原子操作，手机端「采用草稿」与超时认领互斥，不会重复发送。

## 4. 风险

- **不可撤回**：提交后的回复不能删改。论坛侧一旦收到就是既成事实。
- **5 分钟内可能看不到手机通知**：送达即计时，不是「你看过才计时」。Telegram 推送被
  系统静音/折叠也照样计时。
- **正文不会二次人工校对**：草稿由 Kimi 生成，只有你在 5 分钟内点「拒绝」才拦得住。
- **依赖 Telegram**：未绑定 Telegram 时 `/approval` 直接报错，自动发表无法启用，
  仍是纯人工确认。
- **依赖电脑在线**：扩展需保持运行，休眠超过 90 秒的任务作废。
- **本地只读模式仍在**：本版仍不采集，草稿只能基于上游已发布的存档；自动发表只解决
  「谁来点发送」，不解决「内容从哪来」。
